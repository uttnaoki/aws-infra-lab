# ログイン画面の使い方

## 起動

変更はローカル画面と配信処理のみです。既存のCognito認証方式を使うため、この変更でSAMの再デプロイは不要です。コード編集はAI、サーバー起動・デプロイ・認証操作は本人が行います。

既にローカルサーバーが起動中なら、そのターミナルでCtrl+Cを押してから再起動してください。

ターミナルで、このプロジェクトのルートフォルダー（`local.py` がある場所）を開いて実行します。

```sh
set -a
source .env
set +a
python3 local.py
```

ブラウザーで http://127.0.0.1:8080 を開きます。

## 開発者の初期設定

初回は `cp .env.example .env` で設定用ファイルを作成します。CloudFormationの `infra-notes-dev` →「出力」から、`ApiUrl` を `.env` の `API_URL`、`ClientId` を `COGNITO_CLIENT_ID` に設定します。UserPoolIdとは別です。上の起動手順で環境変数として読み込みます。自動で `.env` を読む仕組みではありません。変更後は再起動します。

Gitには値が空の `.env.example` とコードを含め、実際の `.env` は `.gitignore` で除外します。既に追跡済みのファイルは `.gitignore` だけでは除外されません。CIなどでは同じ環境変数を実行環境から渡せます。

ローカルサーバーが環境変数から公開設定の `/config.json` を返し、画面が読み込みます。配信するのはAPI URLと公開クライアントIDの2項目のみで、全環境変数は公開しません。この2項目はブラウザーから見えるため、環境変数化は秘密にするためではなく、環境ごとの設定をコードから分離するためです。パスワードやAWS秘密鍵を公開設定に追加しないでください。静的ホスティングに移す際は、ビルド・デプロイ時に同等の公開設定を生成する方式へ変更します。

## AWSにログイン

1. アプリのログイン画面を開く。
2. 接続設定の入力は不要。
3. Cognitoで作成したメモアプリ用ユーザーのユーザー名・パスワードを入力。
4. 初回の一時パスワードなら、新しいパスワードと確認欄を入力。
5. ログイン後、画面に「AWS環境・シドニー」と表示されていることを確認する。
6. メモを保存し、「再読み込み」で一覧に出ることを確認する。
7. ログアウトし、再ログインして保存済みメモを確認する。

パスワードやトークンをチャット・ログに貼り付ける必要はありません。パスワードを忘れた場合は管理者がCognitoでリセットします。新規登録・メール確認・確認コード再送の画面は [アカウント作成](05-signup.md) を参照してください。パスワード再発行・MFAの画面は未実装です。

## ローカル練習

「ローカルの練習用メモを開く」ではCognitoにログインせず、従来の固定ユーザーとSQLiteを使用します。AWSのメモとは別の保存先です。

## 実装と制約

- `frontend/auth.mjs`：既存のUSER_PASSWORD_AUTHとNEW_PASSWORD_REQUIREDに対応。ブラウザーからCognitoのHTTPSエンドポイントへ直接送信。
- `frontend/app.mjs`：画面切替、API呼び出し、メモ表示。API Gatewayがトークンの正当性を検証。
- `frontend/index.html`：ログイン、初回変更、メモの画面。
- `local.py`：公開するファイルを固定リストで配信。パスワードをローカルサーバーへ送らない。
- 接続先とClientIdは、環境変数から生成される `/config.json` から読み込む。localStorageは使用しない。認証情報はJavaScriptのメモリ内のみ。再読み込み・タブ終了で失われる。
- 現在のテンプレートのIDトークン有効期間（1時間）で再ログインを促す。期限・認証エラーはAPI側でも判定する。自動更新は未実装。
- ログアウトはこの画面の認証情報を消す操作。発行済みトークンのサーバー側失効や他端末からのログアウトは行わない。
- 学習用として既存のパスワード認証に画面を付けたもの。本番化ではCognitoマネージドログインと認可コード＋PKCE、セッション管理を改めて検討する。
- AWS上の実ユーザーでのログイン・メモ保存は本人が実施して結果を確認する。自動テストは認証APIをモックしたもの。
