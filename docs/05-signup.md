# アプリからのアカウント作成

## 動作

「アカウント作成」でユーザー名・メールアドレス・パスワードを入力し、メールの確認コードを送信します。確認完了後はユーザー名とパスワードでログインします。確認画面はログイン画面からも開け、ページを閉じた後でも確認や再送ができます。確認処理だけではログインしません。

既存ユーザーを維持するため、ユーザープールのログイン方式・必須属性スキーマは変更しません。メールは登録画面で必須にし、Cognitoの自動検証対象に設定します。APIを直接使ってメールなしで登録した場合も、自動確認用のトリガーはなく、未確認ユーザーのままです。ユーザー名ログインなのでメールアドレスの一意性は保証しません。

管理者限定登録を解除するため、反映後はインターネットから新規登録が可能になります。既存のJWT認証とメモの所有者分離は維持します。パスワードやトークンをブラウザーの永続保存領域に保存しません。

Cognito標準メール配信を使い、SESの追加設定や有料プランへの変更は行いません。標準配信には1日50通の上限があります。上限に達しても未確認ユーザーが作成される場合があるため、登録し直すのではなく、時間をおいて確認コードを再送します。

## 反映（本人が実行）

アプリのルートフォルダーで環境変数を読み込みます。

```sh
set -a
source .env
set +a
sam validate --lint
sam build
sam deploy --profile "$AWS_PROFILE" --region "$AWS_REGION" --confirm-changeset
```

変更セットでユーザープールが更新対象であることを確認します。既存ユーザープールやテーブルの削除・置換が出た場合は適用せず確認してください。AWS側の更新完了後、[公開手順](04-publish.md)の手順3・4で公開ファイルを再生成してアップロードします。ローカルのコード変更だけでは公開サイトには反映されません。

## 確認項目

- 既存ユーザーでログインし、保存済みメモを取得できる。
- 新しいユーザーで登録し、メールを受信できる。
- 未確認の状態ではログインできず、正しいコードで確認後にログインできる。
- コード間違い・期限切れ・再送時に案内が表示される。
- 新規ユーザーから既存ユーザーのメモは見えない。
- 新規ユーザーのメモ保存・再ログイン後の取得ができる。

本変更のAWS反映、実メール送信、公開画面での登録は未検証です。ローカルのテストはCognitoをモックして検証します。
