# 演習02：AWSに同じ構成を再現する

この手順は準備済みですが、AWS上での実行は未検証です。AWS CLI・SAM CLIは作成時の端末にはありませんでした。まず公式手順で両方とPython 3.13をインストールしてください。AWSでは利用料が発生する可能性があります。対象アカウントを確認し、予算通知を設定してください（通知は課金の強制停止ではありません）。

## 1. 検証して構築する

AWS CLIで学習用アカウントの認証を設定し、このプロジェクトのディレクトリで実行します。

```sh
aws sts get-caller-identity
sam validate --lint
sam build
sam deploy --guided
```

初回の目安：Stack Name=`infra-notes-dev`、Region=`ap-southeast-2`。変更セットを確認する設定はYes。IAMロール作成はテンプレートの権限を確認して許可します。APIの認証はCognito JWTで設定済みです。予期せぬ認証なしAPIの警告が出たら設定を見直してください。

出力のApiUrl・UserPoolId・ClientIdを控えます。画面はまだクラウドにホストせず、手元からAWS APIに接続します。

## 2. 学習用ユーザーを作る

AWSコンソールのCognitoで、出力されたUserPoolIdを選択。ユーザーを作成し、ユーザー名と一時パスワードを設定します。招待メッセージは送信しません。

ユーザー作成後は [ログイン画面の手順](03-login-screen.md) に進みます。ターミナルでのトークン取得は不要です。

## 3. 画面から接続する

`python3 local.py` で起動し、`http://127.0.0.1:8080` を開きます。開発者が[ログイン画面の手順](03-login-screen.md)に従って環境変数を設定したうえで、作成したユーザーでログインします。初回パスワード変更も画面で行います。

## 4. 確認項目

- 認証ヘッダーなしでAWSの `/notes` にアクセスすると401になる。
- 1人目で保存したメモは、2人目のトークンで一覧取得しても表示されない。
- Lambdaのログに認証情報やメモ本文を出力していない。
- API Gateway、Lambda、DynamoDBを構成図と照合できる。

この段階ではIDトークンをAPI認証に利用します。本番向けにはマネージドログイン、認可スコープを持つアクセストークン、更新・ログアウトを設計する演習を追加します。

## 5. 片付けと再現

```sh
sam delete --stack-name infra-notes-dev --region ap-southeast-2
```

学習用データ・ユーザーも削除されます。削除対象を確認してください。その後もう一度デプロイし、手作業の差分を記録します。アプリのテーブルだけでなく、SAMの成果物保存用S3・関連ログ等の残存も確認してください。

## 改善課題

SAMの構成再現と、データの復元は別の問題です。PITRやバックアップは未設定なので、後の復旧演習で追加します。現在のレート制限は予算上限を保証しません。費用計測、アラーム、依存パッケージの固定も次の段階で扱います。
